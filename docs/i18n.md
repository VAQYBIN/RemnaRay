# Localization

Public pages use `/ru` and `/en` locale prefixes. `rr_lang` is the locale
cookie; when it is absent, next-intl falls back to the request language and
then to `settings.locale.default`. Next.js 16 calls the entrypoint `proxy.ts`;
it provides the locale negotiation that the specification describes as
middleware.

## Catalogs are data

Catalog files stay flat and use dotted keys under `locales/<lang>/*.json`
(section 18.4). The directory is mounted read-only into the applications
(`RR_LOCALES_DIR`, `/locales` in Compose), so texts can be replaced without a
rebuild. Arrays and objects — `landing.features`, `landing.faq` — are stored as
JSON values under a single key.

`@remnaray/i18n-core` reads those files. Nothing ships a compiled-in copy of the
catalog any more: the bot receives its messages from
`GET /api/internal/v1/i18n/:lang`, and the site reads
`GET /api/v1/public/i18n/:lang/:namespace`.

## Resolution order

`I18nService` resolves a key as `locale_overrides` → the `<lang>` file → the
`en` file → the key itself (FR-181). Merged namespaces are cached in Valkey
under `rr:i18n:<lang>:<ns>` for five minutes and dropped on `rr:i18n.changed`.
The site revalidates catalogs every five seconds, so an override is visible
within the AC-181 window.

## Legal documents

`locales/<lang>/legal/{terms,privacy,offer}.md` are edited as whole documents.
`GET /api/v1/public/legal/:doc?lang=` applies the stored override, substitutes
`{brand}`, `{domain}` and `{support}`, and reports the revision date. The web
pages render the result with HTML escaping and a small block renderer, and
revalidate every 300 seconds.

## Checks

`pnpm i18n-check` verifies, for every namespace and both languages:

- key parity against the `en` base, including array and object leaves;
- that every message compiles as ICU MessageFormat;
- that the named `{placeholders}` match the `en` message exactly;
- that the Russian catalog is not left holding English copy;
- that each legal document starts with a heading and uses `{brand}`,
  `{domain}` and `{support}`.

## SEO

The public site exposes localized canonical and alternate URLs, `x-default`
pointing at `settings.locale.default`, a localized title and description,
`robots.txt`, and a sitemap built from the enabled locales. Private account,
payment, admin, and setup paths are excluded from crawling.
