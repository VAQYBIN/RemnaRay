# Localization

Public pages use `/ru` and `/en` locale prefixes. `rr_lang` is the locale
cookie; when it is absent, next-intl falls back to the request language and
then Russian. Next.js 16 calls the entrypoint `proxy.ts`; it provides the
locale negotiation that the specification describes as middleware.

Catalog files remain flat and use dotted keys under `locales/<lang>/*.json`.
The web request loader expands those keys for next-intl. `pnpm i18n-check`
verifies that every namespace has the same keys in both supported languages.
Legal documents live beside the catalogs as Markdown and are rendered with
HTML escaping and a small supported-block renderer.

The public site exposes localized canonical and alternate URLs, a localized
title and description, `robots.txt`, and a sitemap containing the landing and
legal routes. Private account, payment, admin, and setup paths are excluded
from crawling.
